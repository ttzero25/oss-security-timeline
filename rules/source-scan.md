# Source scan rule

Treat an external-input to dangerous-operation match as a hypothesis. Record the analyzed commit, stable tracking ID, source and sink files, every cited call hop, and scan coverage. The Python scanner traces request fields, CLI input and HTTP route parameters through simple assignments and bounded cross-module function or statically resolvable instance-method calls. A module-level literal mapping assigned once and never mutated is treated as a fixed allowlist boundary; mutated mappings remain tainted. The JavaScript/TypeScript scanner isolates ordinary named and arrow-function scopes and follows a bounded subset of relative ESM/CommonJS function calls. Dynamic imports, computed dispatch, callbacks, closures, destructured request fields, and full language semantics remain outside this model.

Current dangerous operations include shell-enabled subprocess calls, code evaluation, Python pickle loading, outbound URL requests, dynamic SQL query text, server-side template strings, selected filesystem path operations, explicit signature-verification bypass, and bounded authorization-state mistakes. The Python authorization model reports only two narrow candidates: an authenticated destructive route that loads an external object key without a visible principal/owner scope, and request data written directly to a privilege-bearing field without a visible privileged guard. Owner-scoped lookups, explicit principal checks, and administrator/permission decorators suppress these candidates. This is not a general proof of missing authorization and framework middleware still requires human review. Parameterized SQL with constant query text is excluded. An observed pattern alone is insufficient to claim a vulnerability; inspect upstream guards, path boundaries, deployment defaults and the real effect before progressing.

The Go scanner follows a bounded subset of same-package and local-module function calls. It models common net/http and CLI sources, shell invocations through `exec.Command("sh", "-c", value)`, outbound `net/http` requests, dynamic database query text, and selected `os` path operations. Interface dispatch, goroutine/channel flows, closures, generated code, build tags, and full Go type semantics remain outside this model. Direct argv execution without a shell is not treated as command injection.

When the supported-file count exceeds the scan limit, files changed in recent commits are selected first and all remaining files are ordered deterministically by path. Coverage must report eligible, inspected, prioritized, and skipped counts. A cached audit may be reused only for the same repository, commit, checkout path, and file limit while the Git worktree is clean; public advisory context is refreshed independently.
