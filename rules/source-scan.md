# Source scan rule

Treat an external-input to dangerous-operation match as a hypothesis. Record the analyzed commit, stable tracking ID, source and sink files, every cited call hop, and scan coverage. The Python scanner traces request fields, CLI input and HTTP route parameters through simple assignments and bounded cross-module function or statically resolvable instance-method calls. A module-level literal mapping assigned once and never mutated is treated as a fixed allowlist boundary; mutated mappings remain tainted. The JavaScript/TypeScript scanner isolates ordinary named and arrow-function scopes and follows a bounded subset of relative ESM/CommonJS function calls. Dynamic imports, computed dispatch, callbacks, closures, destructured request fields, and full language semantics remain outside this model.

Current dangerous operations include shell-enabled subprocess calls, code evaluation, Python pickle loading, outbound URL requests, dynamic SQL query text, server-side template strings, selected filesystem path operations, explicit signature-verification bypass, and bounded authorization-state mistakes. The Python authorization model reports only two narrow candidates: an authenticated destructive route that loads an external object key without a visible principal/owner scope, and request data written directly to a privilege-bearing field without a visible privileged guard. Owner-scoped lookups, explicit principal checks, and administrator/permission decorators suppress these candidates. The concurrency model is likewise narrow: it requires a security-named module-level mutable container, a route or async entry, a check followed by mutation, and no visible lock, mutex, semaphore, or acquire call. It records CWE-362 candidates for manual review and treats a visible lock as a conservative suppression; it does not prove the runtime's scheduling or cross-process storage behavior. These models are not general proofs of missing authorization or exploitable races, and framework middleware still requires human review. Parameterized SQL with constant query text is excluded. An observed pattern alone is insufficient to claim a vulnerability; inspect upstream guards, path boundaries, deployment defaults and the real effect before progressing.

The Go scanner follows a bounded subset of same-package and local-module function calls. Standard-library sink calls for `os/exec`, `net/http`, and `os` are tied to their actual import paths and aliases; a local declaration that shadows an import alias conservatively suppresses that binding for the remainder of the function. It models common net/http and CLI sources, shell invocations through `Command("sh", "-c", value)`, outbound `net/http` requests, dynamic database query text, and selected `os` path operations. This is import/symbol resolution rather than full compiler type checking. Interface dispatch, block-precise shadow lifetimes, goroutine/channel flows, closures, generated code, build tags, and full Go type semantics remain outside this model. Direct argv execution without a shell is not treated as command injection.

The C/C++ memory model recognizes numeric local `char`/`uint8_t` stack arrays and selected writes through `read`, `recv`, `fgets`, `gets`, `scanf`, `memcpy`, and `memmove`. Exact `sizeof(destination)` bounds, numeric bounds within capacity, width-limited string scans, and terminating length guards suppress candidates. It does not infer heap allocation sizes, macro values, pointer aliasing, template/container bounds, loop invariants, integer wraparound, or full preprocessor/compiler semantics. A match is a CWE-121 candidate requiring compiler-assisted and runtime review, not proof of exploitability.

When the supported-file count exceeds the scan limit, files changed in recent commits are selected first and all remaining files are ordered deterministically by path. Coverage must report eligible, inspected, prioritized, and skipped counts. A cached audit may be reused only for the same repository, commit, checkout path, and file limit while the Git worktree is clean; public advisory context is refreshed independently.
