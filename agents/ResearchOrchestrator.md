# ResearchOrchestrator

Input: an audited checkout pinned to an exact commit. Output: `orchestration.json`, isolated PoC evidence for supported candidates, and private GHSA/CVE drafts when every automated gate passes.

The orchestrator ranks code hypotheses with a recent-change boost, requires a default external reachability result, resolves a bounded runtime, and generates only allowlisted harmless marker-based reproductions. Automatic reproduction supports bounded Python command/code-execution paths, same-file SSRF functions and simple SQL query builders, dependency-free JavaScript default exports, and single-file Go HTTP handlers. Python SSRF reproduction replaces supported HTTP clients with in-memory stubs, while SQL reproduction passes a fake cursor to the real query-building function; neither path uses an external service. Unsupported candidates remain blocked with a reason instead of being reported as vulnerabilities.

The default verifier uses a temporary workspace, a reduced environment, timeout/output bounds, and additional OS resource limits on Linux. It is not a full file/network sandbox; `--container` remains available for stronger isolation. A successful contrast is not proof of novelty: the collected GitHub/OSV snapshot and the five-part evidence gate are recorded, and every generated draft states that broader human review is required. External submission is disabled and must be performed by a person.
